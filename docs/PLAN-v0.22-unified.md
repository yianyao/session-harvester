## 0. 对提案与两份意见的判断

### 0.1 提案判断：做，且是当前价值密度最高的增量

三点理由，其中第一点是提案自己没有说透的：

1. **它补上了体系缺的成功翼**。现有 G1/G2/G4 全部是失败偏向遥测（错误/重试/放弃/死循环），
   而创造性工作里"好决策怎么演进出来的"在统计口径里完全不可见。主题思维链 = 成功轨迹记录仪，
   与 v0.21 P2-1 report-chains（死循环检测，失败翼）正好合龙成完整的一套。
2. **数据可行性已被两轮核验证实**：「叙事节奏」簇 41 会话/550 消息、标题时间序 18 行
   演进链（节奏→氛围→克制→人物→设定→逻辑→意象）机械可见；reasoning 已以 note 角色
   入库（dsh.py:344）；messages.raw 存原文。原料齐备。
3. **纯增量**：draft/pack/锚点/指纹/只读 API 纪律全部复用，topics 目录 9 个文件天然
   成为注册表雏形。不推翻任何已建的东西。

"过程比产物更值钱"（为什么从 v1 改到 v2 比三个版本加起来更可迁移）——判断成立，
且两层受益（人的写作/设计能力 + skill 进化）都成立。

### 0.2 三个分歧点的裁决

| 分歧 | 意见一（核验完毕.txt） | 意见二（提案核验） | **裁决** |
|---|---|---|---|
| 思维链产物形态 | topic-chain **长文**（frontmatter: topic/members/anchors/stages），存 topics 目录，不塞 §8 卡片 | 新增第四种卡片类型 `evolution`，多锚点长引用 | **采意见一**。卡片保持原子粒度——§8 规范刚在 P0-1 修信任问题，不宜再扩语义；链是"一段演进"不是"一个洞察"，硬塞卡片必丢最值钱的多稿对比。多锚点/长引用问题随之消解（长文自带 stages 结构）。`agent_suggest.py:161/175` 的 100 字截断仍修（建议池展示用） |
| 主题从哪来 | 注册表先行：9 个 topics 文件做顶 + 手工注册 | 标题 n-gram 自动聚类（第 1 步） | **采意见一为主、意见二为辅**。"按作品聚还是按技法聚"是只有用户能判的语义边界（意见二自己也承认未验证聚类质量）；MVP 用注册表，自动聚类（标题 n-gram + 任务签名）降级为注册表的**候选推荐器**，不当权威 |
| 谁改 adapter | 产物演化提取器"绕过 400 字截断"全量解析 args | （未涉及） | **都比预想更难——实测发现 steps 表根本没有 args 列**（cols=sid/seq/ts/tool/phase/status/error/detail），args 仅以 400 字 preview 形态活在 detail（dsh.py:360）。采集库 schema 有指纹守卫，加列动静大；**更稳形态 = 独立"产物提取 pass"**：从原始 jsonl 全量解析 Write/Edit args 产 diff 序列，写独立 meta 库（照 suggestions_meta 范式），采集库零改动 |

### 0.3 事实修正与采纳清单

- ✗ 意见一"A1–A3 仍然优先"：**A1–A3 已于 v0.19 完成**（归一/unresolved/指纹全部在线），
  该意见基于旧状态，勿重复排期。
- ✓ 采纳意见二三条硬约束：跨会话时间序是全新能力（全库 `ORDER BY messages.ts` 零命中实测）、
  draft 24K 单会话预算不可复用（分层下钻替代）、bigram text 列不可用于统计
  （**text 是索引改写文本、原文在 raw**——实测 6079 条 user 消息为 bigram 形态，

- ✓ 采纳意见一：锚点细化到 turn 升为 T 轨硬前置（sid+seq 撑不住"为什么改这一稿"的
  节点定位）；file-history-snapshot 实测为空，稿件演化不走文件快照、走 tool args + 会话文本。
- ✓ 采纳意见一：T 轨 MVP 是**止损线的最佳载体**——与 v0.21 P1-1 采纳闭环合并推进，
  第一份思维链若真帮到一次写作决策，项目存活权即不再是问题。

## 1. 架构定论（不变量沿用 v0.21，T 轨不破例）

```
harvester（确定性引擎）
  ├─ P0–P2 既有项（失败翼：错误/死循环/高频操作）
  └─ T 轨（成功翼：主题/演进/产物）
       ├─ topic register    ← 主题注册表（独立 meta 库；9 个 topics 文件做种子）
       ├─ artifact extract  ← 产物提取 pass（原始 jsonl → Write/Edit diff 序列，绕开 steps 无 args 列）
       ├─ topic chain       ← 跨会话分层时间线（--level 极粗/粗/中/细/产物）
       └─ topic pack        ← 蒸馏包（复用 draft，分层预算）
             ↓ 产物：topic-chain 长文 → topics 目录（独立校验，非 §8 卡片）
             ↓ 只读端点 /api/topics、/api/topic/<id>/chain（挂 db_fingerprint）
Agent（语义层，可抛弃）  → 通读蒸馏包 → 阶段划分 + "怎么想的→怎么变的→为什么"链式叙述
view（只读 + 复制命令）  → 新「主题」tab：左簇列表 / 中时间线（分层切换+diff 芯片）/ 右 chain 文档
```

三不变量重申：view 只读不执行（触发=复制命令）；去重/归一口径单点在 harvester
（**T 轨追加第四条契约：统计与提取一律用 messages.raw，禁用 bigram text 列**）；
产物挂 db_fingerprint。**分析逻辑不焊进前端**——思维链的定义会随认知变（今天看关注点
演进、明天看为什么改这一稿），它是可替换层。

## 2. 路线图

### P0 止血（不变，仍排第一——信任是 T 轨的地基）

P0-1 cards 校验器完整性（块标量/占位符错误级/未核对显式化/反向测试，~50 行）
P0-2 apiserve 接 aggregate_error_roots + view G1 渲染 roots
P0-3 view G3/G4 空态文案带过滤前后计数
P0-4 卡片池目录对齐（start.cmd --cards-root）
P0-5 adapter 补 model 抽取（dsh/autoclaw/vscode_copilot → providerData.model）

### P1 管线与维度（P1-1 立即启动，不等技术项）

P1-1 **采纳闭环 + 止损线**：建议池人工审一遍落 status；**T 轨 MVP（T1）是其载体**——
     第一份真实主题思维链若触发一次真实修改（写作决策或 AGENTS.md 条目），闭环即成。
P1-2 跨建议/跨卡根因去重（normalize_error 唯一键）
P1-3 交叉表 class × harness × model（依赖 P0-5）
P1-4 export-analysis 统一导出器（(class, pattern) 去重，人读/机器读同源）

### T 轨：主题思维链（新增，MVP 先行）

| 项 | 内容 | 规模/验收 |
|---|---|---|
| **T0 前置**（可与 P1 并行） | ① 锚点细化：steps/messages 锚点补 turn 语义（messages 表已有 turn 粒度，打通即可）；② 产物提取 pass 设计：原始 jsonl → Write/Edit args 全量解析 → diff 序列（old_string→new_string）→ 独立 meta 库表；③ text/raw 契约写入 CLAUDE/AGENTS 文档 + 一个防回归测试 | 契约测试：用 bigram text 做统计的代码必须失败 |
| **T1 注册表 MVP + 极粗链** | ① topic register：meta 库 topics 表（id/名称/关键词/成员 sid+证据），`topic register/add/remove` CLI，9 个 topics 文件导入为种子；② 标题时间序链：成员会话标题按时间去重输出（每标题带首现时间）+ 月度分布；③ 落盘挂 db_fingerprint；④ **在真实小说主题手工注册 3–5 会话跑通，产出第一份实际产物** | ~150 行。验收：41 会话「叙事节奏」簇导入后，18 行演进链可复现；产物有人工"聚类粒度对不对"的判定记录 |
| **T2 分层时间线 + 蒸馏包** | `topic chain --topic <id> --level 极粗\|粗\|中\|细\|产物`：极粗=标题序(~2K)/粗=每会话标题+首 user+末 assistant(~10K)/中=user 消息序(~30K)/细=选定会话全回合(按需)/产物=diff 序列+版本对照(按需)；`topic pack` 复用 draft 分层预算 | 验收：五档各自字符预算不爆；细/产物档必须选会话后按需拉取 |
| **T3 Agent 蒸馏 + topic-chain 长文** | Agent 消费 topic pack → 产出 chain 长文（frontmatter: topic/members/anchors/stages；正文=阶段分组+"怎么想的→怎么变的→为什么"，每节点挂 turn 级锚点）→ 存 topics 目录 → **独立校验器**（长文形态，非 §8：锚点必须可回溯、阶段必须有成员证据）→ `/api/topics` `/api/topic/<id>/chain` 只读暴露 | 验收：链上每个"为什么改"节点能一键跳回原文；重跑同主题、同库快照，产物 diff 可归因 |
| **T4 skill 进化 join** | 时间线节点锚点 × skill 调用锚点交叉：某 skill 在 N 次创作推进中各贡献了什么、哪次拖了后腿——创造性工作中 skill 的失败常是"产出平庸"而非报错，只有放进思维链才可见 | 验收：对 1 个真实 skill 出具首次交叉报告 |
| **T5（后期）** | 自动聚类候选推荐器：标题 n-gram + 任务签名（原 v0.21 P2-4 并入），只产候选不改注册表 | 验收：候选准确率由人工判定并记录 |

### P2 其余缺口（次序微调）

P2-1 report-chains（死循环/连击/长回合——失败翼，与 T 轨成功翼合龙）
P2-2 report-keywords（n-gram 词频；**实现必须走 raw 列**——T0 契约的既有适用点）

### P3 明确不做（追加两条）

- view 内不放聚类/时间线/思维链逻辑（分析定义会反复变，必须留在可测试侧）；
- 思维链不塞 §8 卡片规范、不新增卡片类型（裁决 0.2-A）；
- 不为 args 全量回传去改采集库 schema（用独立提取 pass，裁决 0.2-C）。

## 3. 执行顺序

```
P0-1 → P0-2 ∥ P0-3 → P0-4 → P0-5
→ P1-1（人工，立即；含 T1 真实主题选定）
→ T0 ∥ P1-2/P1-4 → T1（MVP，第一份产物）→ P1-3
→ T2 → T3 → P2-1 → T4 → P2-2 → T5
```

理由：P0-1 仍是信任地基（校验器假报成功会污染 T3 的产物校验，同源风险）；
P1-1 与 T1 共享"真实主题"载体，一次人工投入双收；T 轨 MVP（先链后台）在真实主题上
跑通全环后再建 view tab——先让东西值钱，再装橱窗。

## 4. 验收标准（新增 T 轨部分，其余沿用 v0.21 §4）

- **T0**：bigram text 防回归测试存在且当前全绿；产物提取 pass 对任一 Write/Edit 密集
  会话产出 ≥1 条完整 diff（old_string 与 new_string 均非截断）。
- **T1**：「叙事节奏」41 会话导入注册表 → 标题演进链 18 行可复现；人工聚类粒度判定
  （按作品/按技法）有记录。
- **T2**：五档时间线各自不超预算档位；产物档展示同文本的版本序（时间序即版本序）。
- **T3**：chain 长文通过独立校验；任一节点锚点在 view 内跳回原文；同快照重跑产物 diff 可归因。
- **T4**：首个 skill × 时间线交叉报告出具，含至少一次"贡献了什么/拖了后腿"的判定记录。
